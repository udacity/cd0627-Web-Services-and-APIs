## Project Overview

You are a Backend Engineer at a leading e-commerce platform. Recently, the customer support team has been overwhelmed by a high volume of Return Merchandise Authorization (RMA) requests. Currently, human agents must manually read every complaint, check the company's return policy, and decide whether to approve or deny the return. This process is slow, error-prone, and frustrating for customers.

The Director of Engineering has tasked you with automating this process. You need to build an **AI-Powered RMA Engine** that can instantly analyze customer complaints, evaluate them against the return policy, and process the decisions. 

Crucially, the system must be robust. It needs to handle potential outages of the AI provider gracefully, and it must integrate cleanly into the company's broader event-driven architecture using Kafka, allowing other services (like the customer dashboard) to react to approved returns in real-time.

To address this need, you will build a Spring Boot microservice that leverages Spring AI for intelligent processing, Resilience4j for fault tolerance, Spring Kafka for event streaming, and Spring for GraphQL to provide a modern read API for the dashboard.

## Step-by-Step Implementation Guide

### Step 1: Resilient REST Endpoints & Circuit Breakers (Handling AI Outages)
The AI provider occasionally experiences downtime or latency. If the external AI service fails, your application shouldn't crash; it should degrade gracefully. Your task:

1. **Endpoint Mapping:** Open `RmaController.java` and map the `submitReturn` method as a `POST` request at `/api/returns`.
2. **Resilience Decorator:** Annotate the endpoint with a Resilience4j `@CircuitBreaker` named `rmaService`. Ensure the name matches the configuration properties defined in your `application.properties`.
3. **Fallback Logic:** Implement the fallback method `submitReturnFallback`. It must accept the original `ReturnRequest` and a `Throwable` parameter to catch failures, returning a `503 Service Unavailable` HTTP status with a friendly error message indicating the service is temporarily down.

### Step 2: Controller Slice Testing (Fast, Isolated Tests)
Before you integrate the complex AI model, you must write slice tests to verify that your REST endpoint handles normal requests, denied requests, and circuit breaker degradation correctly. Your task:

1. **Mockito Setup:** Open `RmaControllerTest.java` and complete the MockMvc setup. Use `@Mock` to create a mock of `RmaService` and `@InjectMocks` to inject it into the `RmaController`.
2. **Implement Denied Case:** Add a unit test `testSubmitReturn_denied_returns200WithApprovedFalse` verifying that when `RmaService` returns `approved=false`, the endpoint still returns a `200 OK` status with `approved=false` in the response body.
3. **Implement Fallback Case:** Add a test verifying the circuit breaker fallback behavior. Mock the service to throw a `RuntimeException` and assert that the controller handles it gracefully by returning HTTP `503 Service Unavailable`.

### Step 3: Intelligent Complaint Analysis (Structured AI Output)
You need to extract structured details from unstructured customer complaints. Your task:

1. **Structured Parser:** Open `RmaService.java`. In the `processReturn` method, instantiate a `BeanOutputConverter` for the `ReturnAnalysis` record to handle structured JSON schema generation and parsing.
2. **Prompt Engineering:** Build a prompt that combines the customer's raw complaint text and the format instructions generated by `converter.getFormat()`.
3. **Model Request:** Use the `ChatClient` to query the LLM and convert the raw JSON string back into a strongly-typed `ReturnAnalysis` object containing the sentiment, item category, and defect status.

### Step 4: Policy-Aware Decision Making with RAG (Grounding the AI)
The AI needs to evaluate returns against the company's specific return policy, not generic knowledge. Your task:

1. **Vector Store Seeding:** Open `AiConfig.java`. Complete the `seedVectorStore` method to read `policy-seed.txt` and load its contents into the `SimpleVectorStore`. *Ensure you check if `OPENAI_API_KEY` is missing or equal to "mock-key" so the application doesn't crash on startup during local/offline testing.*
2. **grounding Advisor:** Return to `RmaService.java`. Create a `QuestionAnswerAdvisor` backed by your seeded `VectorStore`.
3. **RAG Prompting:** Construct a prompt querying the AI whether the return should be approved based on the `ReturnAnalysis` fields.
4. **Context Retrieval:** Chain the advisor onto the `ChatClient` request (`.advisors(policyAdvisor)`) so the AI makes decisions grounded directly in the store policy documents. Parse the result to determine if the return is approved.

### Step 5: Event-Driven Publishing (CQRS Write Side)
When a return is approved, other microservices in the platform need to react in real-time. Your task:

1. **Conditional Event Trigger:** In `RmaService.java`, check if the return was approved.
2. **Event Instantiation:** If approved, create a `ReturnApprovedEvent` populated with the customer ID, item type, and approval reason.
3. **Kafka Broadcast:** Use the `KafkaTemplate` to publish this event to the topic `returns-topic`. Use the customer ID as the routing key to preserve message ordering.

### Step 6: Dashboard Read Model & GraphQL (CQRS Read Side)
The customer service team needs a real-time view of approved returns. You will build a read model using CQRS and expose it via GraphQL. Your task:

1. **Kafka Listener:** Open `DashboardService.java` and implement the `@KafkaListener(topics = RETURNS_TOPIC, groupId = "dashboard-group")` method to consume approved events. Stash the events in the `dashboardView` map keyed by `customerId`.
2. **GraphQL Query Resolver:** Open `DashboardController.java` and annotate the `returnsDashboard` method with `@QueryMapping` so it can serve the data via the GraphQL endpoint.
3. **Schema Verification:** Open `schema.graphqls` and verify that the GraphQL fields match the Java `ReturnApprovedEvent` record fields exactly.

### Integration Testing: Asynchronous E2E Verification
You must write an integration test that verifies the full Kafka event loop asynchronously. Your task:

1. **Mock Service:** Open `RmaServiceIntegrationTest.java`. Set up Mockito to intercept `RmaService` calls and directly send a mock `ReturnApprovedEvent` to Kafka, bypassing OpenAI dependencies.
2. **Awaitility Assertion:** Use `Awaitility` (`await().atMost(...)`) to poll the dashboard service and assert that the event is successfully consumed and visible in the read model within a few seconds.
